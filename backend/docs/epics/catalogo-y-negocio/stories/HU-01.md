# HU-01 (API) — Consultar información del negocio

| Campo     | Valor                                                                                             |
| --------- | ------------------------------------------------------------------------------------------------- |
| Endpoints | `GET /negocio`, `GET /productos/destacados`, `PUT /admin/negocio`                                 |
| Acceso    | Público (lectura); administrador (edición)                                                        |
| Reglas    | RN-02                                                                                             |
| Frontend  | [HU-01 en la landing](../../../../../landing/docs/epics/informacion-del-negocio/stories/HU-01.md) |

## Historia

> **Como** landing de Nativa 360, **quiero** obtener la información del
> negocio y los productos destacados desde la API, **para** mostrarlos sin
> tenerlos escritos en el código.

## Escenarios

```gherkin
Característica: API de información del negocio

  Escenario: Positivo – obtener la información del negocio
    Dado que el negocio tiene registrados nombre, dirección, teléfono, WhatsApp y redes sociales
    Cuando se hace GET /negocio sin autenticación
    Entonces la respuesta es 200 con esos datos

  Escenario: Positivo – obtener los destacados
    Dado que hay 4 productos activos marcados como destacados
    Cuando se hace GET /productos/destacados
    Entonces la respuesta es 200 con los 4 productos con nombre, imagen, descripción y precio

  Escenario: Negativo – un destacado inactivo no se devuelve
    Dado que uno de los productos destacados está inactivo
    Cuando se hace GET /productos/destacados
    Entonces ese producto no viene en la respuesta

  Escenario: Negativo – un empleado no puede editar la información del negocio
    Dado que un empleado está autenticado
    Cuando hace PUT /admin/negocio
    Entonces la respuesta es 403

  Escenario: Error – la base de datos no responde
    Dado que la base de datos no está disponible
    Cuando se hace GET /negocio
    Entonces la respuesta es 503 con el formato de error estándar

  Esquema del escenario: Validación – edición de la información
    Dado que el administrador está autenticado
    Cuando hace PUT /admin/negocio con <campo> igual a "<valor>"
    Entonces la respuesta es <codigo>

    Ejemplos:
      | campo        | valor                          | codigo |
      | telefono     | 27711234                       | 200    |
      | telefono     | abc                            | 400    |
      | whatsapp     |                                | 400    |
      | instagram_url | no-es-una-url                 | 400    |
```

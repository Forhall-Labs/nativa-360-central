# HU-08 (API) — Administrar productos

| Campo     | Valor                                                                                        |
| --------- | -------------------------------------------------------------------------------------------- |
| Endpoints | `GET /admin/productos`, `POST /admin/productos`, `PATCH /admin/productos/:id`                |
| Acceso    | Administrador (todo); empleado (consultar y editar, sin precio)                              |
| Reglas    | RN-01, RN-03, RN-27                                                                          |
| Frontend  | [HU-08 en el admin](../../../../../admin/docs/epics/gestion-administrativa/stories/HU-08.md) |

## Historia

> **Como** panel de administración, **quiero** crear, editar y deshabilitar
> productos a través de la API, **para** que los cambios se validen y queden
> registrados en un solo lugar.

## Escenarios

```gherkin
Característica: API de administración de productos

  Escenario: Positivo – crear un producto
    Dado que el administrador está autenticado
    Cuando hace POST /admin/productos con código "VIT-001", nombre, descripción, precio 6500, categoría e imagen
    Entonces la respuesta es 201 con el producto creado en estado "activo"
    Y quedan guardados creado_por y fecha_creacion

  Escenario: Positivo – deshabilitar un producto
    Dado que el administrador está autenticado
    Cuando hace PATCH /admin/productos/12 con estado "inactivo"
    Entonces la respuesta es 200
    Y el producto deja de aparecer en GET /productos
    Pero los pedidos que lo incluyen lo siguen mostrando

  Escenario: Negativo – el empleado no puede cambiar el precio
    Dado que un empleado está autenticado
    Cuando hace PATCH /admin/productos/12 con precio 7000
    Entonces la respuesta es 403
    Y el precio no cambia

  Escenario: Negativo – código duplicado
    Dado que ya existe un producto con código "VIT-001"
    Cuando el administrador hace POST /admin/productos con código "VIT-001"
    Entonces la respuesta es 409

  Escenario: Negativo – sin sesión
    Cuando se hace POST /admin/productos sin token
    Entonces la respuesta es 401

  Escenario: Error – falla el almacenamiento de imágenes
    Dado que Supabase Storage no responde
    Cuando el administrador crea un producto con imagen
    Entonces la respuesta es 503
    Y el producto no queda creado a medias

  Esquema del escenario: Validación – datos del producto
    Dado que el administrador está autenticado
    Cuando hace POST /admin/productos con <campo> igual a "<valor>"
    Entonces la respuesta es 400 e indica el campo "<campo>"

    Ejemplos:
      | campo       | valor |
      | nombre      |       |
      | descripcion |       |
      | precio      | 0     |
      | precio      | -500  |
      | imagen_url  |       |
```

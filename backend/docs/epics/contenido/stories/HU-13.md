# HU-13 (API) — Administrar promociones y eventos

| Campo     | Valor                                                                                                                         |
| --------- | ----------------------------------------------------------------------------------------------------------------------------- |
| Endpoints | `GET /promociones`, `GET /eventos`, `GET /contenidos`, `POST/PATCH /admin/promociones`, `/admin/eventos`, `/admin/contenidos` |
| Acceso    | Público (solo vigente); administrador o personal autorizado (edición)                                                         |
| Reglas    | RN-19 a RN-21, RN-37, RN-38, RN-39 a RN-42                                                                                    |
| Frontend  | [HU-13 en el admin](../../../../../admin/docs/epics/clientes-y-contenido/stories/HU-13.md)                                    |

## Historia

> **Como** panel de administración, **quiero** crear y retirar promociones,
> eventos y contenido en la API, **para** que el sitio público muestre solo
> lo vigente sin que nadie tenga que quitarlo a mano.

## Escenarios

```gherkin
Característica: API de promociones, eventos y contenido

  Antecedentes:
    Dado que hoy es 15/11/2026

  Escenario: Positivo – la promoción vigente se publica sola
    Dado que existe una promoción activa del 01/11 al 30/11
    Cuando se hace GET /promociones sin autenticación
    Entonces la respuesta incluye esa promoción

  Escenario: Positivo – crear un evento presencial
    Dado que el administrador está autenticado
    Cuando hace POST /admin/eventos con nombre, fecha, horario y ubicación
    Entonces la respuesta es 201

  Escenario: Negativo – una promoción vencida no se publica
    Dado que existe una promoción activa del 01/10 al 31/10
    Cuando se hace GET /promociones
    Entonces esa promoción no viene en la respuesta

  Escenario: Negativo – dos promociones sobre el mismo producto
    Dado que "Vitamina C 1000 mg" tiene una promoción del 01/11 al 30/11
    Cuando el administrador hace POST /admin/promociones para ese producto del 15/11 al 20/11
    Entonces la respuesta es 409

  Escenario: Negativo – un empleado sin permiso no publica contenido
    Dado que un empleado sin permiso de contenido está autenticado
    Cuando hace POST /admin/contenidos
    Entonces la respuesta es 403

  Escenario: Error – la base de datos no responde
    Dado que la base de datos no está disponible
    Cuando se hace GET /promociones
    Entonces la respuesta es 503

  Esquema del escenario: Validación – fechas y datos
    Dado que el administrador está autenticado
    Cuando hace POST a <recurso> con <dato>
    Entonces la respuesta es 400

    Ejemplos:
      | recurso             | dato                                    |
      | /admin/promociones  | fecha_fin anterior a fecha_inicio       |
      | /admin/promociones  | descuento 0                             |
      | /admin/promociones  | descuento mayor a 100                   |
      | /admin/eventos      | evento presencial sin ubicacion         |
      | /admin/contenidos   | fecha_fin anterior a fecha_inicio       |
```

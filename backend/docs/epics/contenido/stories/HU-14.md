# HU-14 (API) — Administrar visitas del doctor

| Campo     | Valor                                                                                      |
| --------- | ------------------------------------------------------------------------------------------ |
| Endpoints | `GET /visitas-doctor`, `GET/POST/PATCH /admin/visitas-doctor`                              |
| Acceso    | Público (solo confirmadas y futuras); administrador o personal autorizado (edición)        |
| Reglas    | RN-34, RN-35, RN-36                                                                        |
| Frontend  | [HU-14 en el admin](../../../../../admin/docs/epics/clientes-y-contenido/stories/HU-14.md) |

## Historia

> **Como** panel de administración y landing, **quiero** gestionar y
> consultar las visitas del doctor en la API, **para** que la landing muestre
> solo las visitas confirmadas.

## Escenarios

```gherkin
Característica: API de visitas del doctor

  Escenario: Positivo – crear una visita confirmada
    Dado que el administrador está autenticado
    Cuando hace POST /admin/visitas-doctor con doctor, especialidad, fecha 22/11, de 09:00 a 12:00 y estado "confirmada"
    Entonces la respuesta es 201
    Y la visita aparece en GET /visitas-doctor

  Escenario: Negativo – una visita pendiente no se publica
    Dado que existe una visita en estado "pendiente"
    Cuando se hace GET /visitas-doctor
    Entonces esa visita no viene en la respuesta

  Escenario: Negativo – una visita cancelada deja de publicarse
    Dado que existe una visita confirmada
    Cuando el administrador hace PATCH /admin/visitas-doctor/<id> con estado "cancelada"
    Entonces la visita deja de aparecer en GET /visitas-doctor

  Escenario: Negativo – sin sesión
    Cuando se hace POST /admin/visitas-doctor sin token
    Entonces la respuesta es 401

  Escenario: Error – la base de datos no responde
    Dado que la base de datos no está disponible
    Cuando se hace GET /visitas-doctor
    Entonces la respuesta es 503

  Esquema del escenario: Validación – horario
    Dado que el administrador está autenticado
    Cuando hace POST /admin/visitas-doctor con hora_inicio "<inicio>" y hora_fin "<fin>"
    Entonces la respuesta es <codigo>

    Ejemplos:
      | inicio | fin   | codigo |
      | 09:00  | 12:00 | 201    |
      | 12:00  | 09:00 | 400    |
      | 09:00  | 09:00 | 400    |
      | 25:00  | 26:00 | 400    |
```

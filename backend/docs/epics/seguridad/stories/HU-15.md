# HU-15 (API) — Gestionar usuarios y permisos

| Campo     | Valor                                                                                     |
| --------- | ----------------------------------------------------------------------------------------- |
| Endpoints | `GET/POST/PATCH /admin/usuarios`, `GET /admin/yo` (usuario y rol actual)                  |
| Acceso    | Solo administrador (gestión); cualquier usuario interno (`/admin/yo`)                     |
| Reglas    | RN-27, RN-28                                                                              |
| Frontend  | [HU-15 en el admin](../../../../../admin/docs/epics/usuarios-y-permisos/stories/HU-15.md) |

## Historia

> **Como** administrador, **quiero** que la API administre las cuentas
> internas y valide el rol en cada operación, **para** que nadie haga más de
> lo que su rol permite.

## Escenarios

```gherkin
Característica: API de usuarios y permisos

  Escenario: Positivo – crear un usuario interno
    Dado que el administrador está autenticado
    Cuando hace POST /admin/usuarios con nombre, correo "maria@nativa360.com" y rol "empleado"
    Entonces la respuesta es 201
    Y se crea la cuenta en Supabase Auth sin guardar contraseñas en la base de la API

  Escenario: Positivo – consultar el rol actual
    Dado que María está autenticada con rol "empleado"
    Cuando hace GET /admin/yo
    Entonces la respuesta es 200 con su nombre y rol "empleado"

  Escenario: Negativo – un empleado no puede gestionar usuarios
    Dado que María está autenticada con rol "empleado"
    Cuando hace POST /admin/usuarios
    Entonces la respuesta es 403

  Escenario: Negativo – usuario deshabilitado
    Dado que la cuenta de María está deshabilitada
    Cuando María llama a cualquier endpoint /admin con un token válido
    Entonces la respuesta es 403

  Escenario: Negativo – token vencido o alterado
    Cuando se llama a GET /admin/yo con un token vencido o con la firma alterada
    Entonces la respuesta es 401

  Escenario: Negativo – no puede quedar el sistema sin administrador
    Dado que hay un solo usuario con rol "administrador"
    Cuando hace PATCH /admin/usuarios/<su id> con rol "empleado"
    Entonces la respuesta es 409

  Escenario: Error – no se puede verificar el token
    Dado que no se puede descargar el JWKS de Supabase y no hay una copia en cache
    Cuando se llama a GET /admin/yo
    Entonces la respuesta es 503
    Y la solicitud no se trata como autenticada

  Esquema del escenario: Validación – datos del usuario
    Dado que el administrador está autenticado
    Cuando hace POST /admin/usuarios con correo "<correo>" y rol "<rol>"
    Entonces la respuesta es <codigo>

    Ejemplos:
      | correo                | rol           | codigo |
      | pedro@nativa360.com   | empleado      | 201    |
      | maria@nativa360.com   | empleado      | 409    |
      | pedro@                | empleado      | 400    |
      | pedro@nativa360.com   | superusuario  | 400    |
```

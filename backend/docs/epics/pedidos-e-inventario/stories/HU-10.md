# HU-10 (API) — Actualizar el estado de un pedido

| Campo     | Valor                                                                                        |
| --------- | -------------------------------------------------------------------------------------------- |
| Endpoints | `GET /admin/pedidos/:id`, `PATCH /admin/pedidos/:id/estado`                                  |
| Acceso    | Administrador, empleado                                                                      |
| Reglas    | RN-14 a RN-17, RN-33                                                                         |
| Frontend  | [HU-10 en el admin](../../../../../admin/docs/epics/gestion-administrativa/stories/HU-10.md) |

## Historia

> **Como** panel de administración, **quiero** cambiar el estado de un pedido
> a través de la API, **para** que solo se permitan transiciones válidas y
> quede registrado quién hizo cada cambio.

## Escenarios

```gherkin
Característica: API de estados de pedido

  Antecedentes:
    Dado que existe el pedido "N360-0042" en estado "pendiente"
    Y que un empleado está autenticado

  Escenario: Positivo – cambiar el estado
    Cuando hace PATCH /admin/pedidos/N360-0042/estado con "en_revision" y la observación "Coordinando"
    Entonces la respuesta es 200
    Y se agrega una fila en estados_pedido con el estado, la observación, el usuario_id y la fecha

  Escenario: Negativo – transición inválida
    Dado que el pedido está "entregado"
    Cuando hace PATCH /admin/pedidos/N360-0042/estado con "pendiente"
    Entonces la respuesta es 409

  Escenario: Negativo – cancelar un pedido pagado sin revisar el reembolso
    Dado que el pedido está "confirmado"
    Cuando hace PATCH /admin/pedidos/N360-0042/estado con "cancelado" sin observación
    Entonces la respuesta es 400 e indica que se requiere la observación del reembolso

  Escenario: Negativo – un cliente no puede cambiar estados
    Dado que la clienta dueña del pedido está autenticada
    Cuando hace PATCH /admin/pedidos/N360-0042/estado
    Entonces la respuesta es 403

  Escenario: Error – la base de datos no responde
    Dado que la base de datos no está disponible
    Cuando el empleado hace PATCH /admin/pedidos/N360-0042/estado
    Entonces la respuesta es 503
    Y el estado y su historial no quedan inconsistentes

  Esquema del escenario: Validación – estados permitidos
    Dado que el pedido está en "<actual>"
    Cuando el empleado lo cambia a "<nuevo>"
    Entonces la respuesta es <codigo>

    Ejemplos:
      | actual      | nuevo       | codigo |
      | pendiente   | en_revision | 200    |
      | en_revision | confirmado  | 200    |
      | confirmado  | preparado   | 200    |
      | preparado   | entregado   | 200    |
      | pendiente   | entregado   | 409    |
      | pendiente   | enviado     | 400    |
```

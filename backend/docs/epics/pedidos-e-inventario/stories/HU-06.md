# HU-06 (API) — Registrar un pedido

| Campo     | Valor                                                                                   |
| --------- | --------------------------------------------------------------------------------------- |
| Endpoints | `POST /pedidos`, `GET /pedidos/mios`                                                    |
| Acceso    | Cliente autenticado                                                                     |
| Reglas    | RN-05, RN-09, RN-12, RN-24, RN-26                                                       |
| Frontend  | [HU-06 en el e-com](../../../../../e-com/docs/epics/carrito-y-pedidos/stories/HU-06.md) |

## Historia

> **Como** e-commerce de Nativa 360, **quiero** registrar el pedido del
> cliente en la API con los precios y existencias validados en el servidor,
> **para** que el personal reciba pedidos correctos.

## Escenarios

```gherkin
Característica: API de registro de pedidos

  Antecedentes:
    Dado que "Omega 3" está activo, cuesta ₡8 000 y tiene 10 unidades
    Y que la clienta "Ana Mora" está autenticada

  Escenario: Positivo – registrar el pedido
    Cuando hace POST /pedidos con 2 unidades de "Omega 3"
    Entonces la respuesta es 201 con el código del pedido, estado "pendiente" y total estimado 16000
    Y el detalle guarda el precio unitario de ₡8 000
    Y las existencias de "Omega 3" siguen en 10

  Escenario: Positivo – el total lo calcula el servidor
    Cuando hace POST /pedidos con 2 unidades de "Omega 3" y un total de 100
    Entonces el pedido se registra con total estimado 16000

  Escenario: Positivo – cada cliente ve solo sus pedidos
    Dado que "Ana Mora" tiene 3 pedidos y otro cliente tiene 5
    Cuando "Ana Mora" hace GET /pedidos/mios
    Entonces la respuesta trae solo sus 3 pedidos

  Escenario: Negativo – sin sesión
    Cuando se hace POST /pedidos sin token
    Entonces la respuesta es 401

  Escenario: Negativo – existencias insuficientes
    Cuando "Ana Mora" hace POST /pedidos con 11 unidades de "Omega 3"
    Entonces la respuesta es 409 e indica que hay 10 unidades disponibles

  Escenario: Negativo – producto inactivo
    Dado que "Té de manzanilla" está inactivo
    Cuando "Ana Mora" hace POST /pedidos con "Té de manzanilla"
    Entonces la respuesta es 409 e indica el producto no disponible

  Escenario: Error – falla la base de datos a mitad del registro
    Dado que la base de datos falla después de guardar el pedido y antes de guardar el detalle
    Cuando "Ana Mora" hace POST /pedidos
    Entonces la respuesta es 503
    Y no queda un pedido sin detalle (la operación es una transacción)

  Esquema del escenario: Validación – cuerpo del pedido
    Cuando "Ana Mora" hace POST /pedidos con <cuerpo>
    Entonces la respuesta es 400

    Ejemplos:
      | cuerpo                                  |
      | una lista de productos vacía            |
      | una cantidad de 0                       |
      | una cantidad negativa                   |
      | un producto_id que no es un identificador |
      | el mismo producto repetido dos veces    |
```

# HU-09 (API) — Gestionar el inventario

| Campo     | Valor                                                                                                          |
| --------- | -------------------------------------------------------------------------------------------------------------- |
| Endpoints | `GET /admin/inventario`, `POST /admin/inventario/movimientos`, `GET /admin/inventario/:productoId/movimientos` |
| Acceso    | Administrador, empleado                                                                                        |
| Reglas    | RN-04, RN-06, RN-27                                                                                            |
| Frontend  | [HU-09 en el admin](../../../../../admin/docs/epics/gestion-administrativa/stories/HU-09.md)                   |

## Historia

> **Como** panel de administración, **quiero** registrar movimientos de
> inventario a través de la API, **para** que las existencias cambien solo
> con un motivo y un responsable registrados.

## Escenarios

```gherkin
Característica: API de inventario

  Antecedentes:
    Dado que "Omega 3" tiene 10 unidades
    Y que un empleado está autenticado

  Escenario: Positivo – registrar una entrada
    Cuando hace POST /admin/inventario/movimientos con tipo "entrada", 24 unidades de "Omega 3" y motivo "Pedido al proveedor"
    Entonces la respuesta es 201
    Y "Omega 3" queda con 34 unidades
    Y el movimiento guarda el usuario_id del empleado y la fecha

  Escenario: Positivo – ajuste por conteo físico
    Cuando hace POST /admin/inventario/movimientos con tipo "ajuste", cantidad 8 y motivo "Conteo físico"
    Entonces "Omega 3" queda con 8 unidades

  Escenario: Negativo – salida mayor a las existencias
    Cuando hace POST /admin/inventario/movimientos con tipo "salida" y 15 unidades
    Entonces la respuesta es 409
    Y las existencias siguen en 10

  Escenario: Negativo – sin sesión
    Cuando se hace POST /admin/inventario/movimientos sin token
    Entonces la respuesta es 401

  Escenario: Error – dos movimientos al mismo tiempo
    Dado que dos empleados registran una salida de 6 unidades al mismo tiempo
    Cuando la API procesa ambos movimientos
    Entonces solo uno se aplica y el otro responde 409
    Y las existencias nunca quedan negativas

  Esquema del escenario: Validación – cuerpo del movimiento
    Cuando hace POST /admin/inventario/movimientos con tipo "<tipo>", cantidad "<cantidad>" y motivo "<motivo>"
    Entonces la respuesta es <codigo>

    Ejemplos:
      | tipo      | cantidad | motivo  | codigo |
      | entrada   | 5        | Compra  | 201    |
      | entrada   | 0        | Compra  | 400    |
      | entrada   | 5        |         | 400    |
      | entrada   | 2.5      | Compra  | 400    |
      | regalo    | 5        | Compra  | 400    |
```

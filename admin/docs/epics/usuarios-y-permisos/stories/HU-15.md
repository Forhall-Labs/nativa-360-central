## Historia

> **Como** administrador, **quiero** registrar, modificar, activar o
> deshabilitar las cuentas del personal y asignarles un rol, **para** que cada
> persona use solo las funciones que le corresponden.

## Escenarios

```gherkin
Característica: Gestionar usuarios y permisos

  Antecedentes:
    Dado que el administrador inició sesión en el panel

  Escenario: Positivo – crear un usuario con rol de empleado
    Dado que el administrador está en "Usuarios"
    Cuando crea a "María Solís" con el correo "maria@nativa360.com" y el rol "empleado"
    Entonces la cuenta queda activa
    Y María puede iniciar sesión y ve solo Pedidos, Productos, Inventario y Clientes

  Escenario: Positivo – cerrar sesión
    Dado que María inició sesión
    Cuando presiona "Cerrar sesión"
    Entonces vuelve a la pantalla de inicio de sesión
    Y no puede volver al panel con el botón "Atrás" del navegador

  Escenario: Negativo – un empleado no puede gestionar usuarios
    Dado que María inició sesión con el rol "empleado"
    Cuando intenta abrir "/usuarios" escribiendo la dirección
    Entonces ve "No tenés permiso para esta acción"

  Escenario: Negativo – un usuario deshabilitado no puede entrar
    Dado que el administrador deshabilitó la cuenta de María
    Cuando María intenta iniciar sesión
    Entonces ve "Tu cuenta está deshabilitada. Consultá con el administrador"

  Escenario: Negativo – el administrador no puede quitarse su propio rol
    Dado que el administrador es el único con rol "administrador"
    Cuando intenta cambiar su propio rol a "empleado"
    Entonces ve "Tiene que quedar al menos un administrador"
    Y su rol no cambia

  Escenario: Error – el servicio de autenticación no responde
    Dado que Supabase Auth no está disponible
    Cuando María intenta iniciar sesión
    Entonces ve "No se pudo iniciar sesión. Intentá de nuevo en unos minutos"
    Y la contraseña no se muestra ni se guarda en el navegador

  Esquema del escenario: Validación – datos del usuario
    Dado que el administrador está creando un usuario
    Cuando ingresa el correo "<correo>"
    Entonces <resultado>

    Ejemplos:
      | correo                | resultado                                         |
      | pedro@nativa360.com   | el usuario se crea                                |
      | maria@nativa360.com   | ve "Ya existe un usuario con ese correo"          |
      | pedro@                | ve "Ingresá un correo válido"                     |
      |                       | ve "El correo es obligatorio"                     |

  Esquema del escenario: Permisos por rol
    Dado que inició sesión un usuario con el rol "<rol>"
    Cuando intenta <accion>
    Entonces la acción <resultado>

    Ejemplos:
      | rol           | accion                         | resultado     |
      | administrador | cambiar el precio de un producto | se permite  |
      | empleado      | cambiar el precio de un producto | se rechaza  |
      | empleado      | actualizar existencias         | se permite    |
      | empleado      | asignar un rol                 | se rechaza    |
      | administrador | asignar un rol                 | se permite    |
```

# HU-10 — Actualizar el estado de un pedido

| Campo      | Valor                                                                                          |
| ---------- | ---------------------------------------------------------------------------------------------- |
| Usuario    | Empleado o administrador                                                                       |
| Prioridad  | Alta                                                                                           |
| Riesgo     | Medio                                                                                          |
| Sprint     | 5 · Gestión administrativa                                                                     |
| Puntos     | Por determinar                                                                                 |
| Requisitos | MO-23, MO-24                                                                                   |
| Reglas     | RN-10, RN-13 a RN-17, RN-33                                                                    |
| API        | [HU-10 en el backend](../../../../../backend/docs/epics/pedidos-e-inventario/stories/HU-10.md) |

## Historia

> **Como** empleado, **quiero** consultar los pedidos y actualizar su estado
> según avanza su gestión, **para** que todo el equipo y el cliente sepan en
> qué va cada pedido.

## Escenarios

```gherkin
Característica: Actualizar el estado de un pedido

  Antecedentes:
    Dado que existe el pedido "N360-0042" en estado "pendiente" por ₡16 000
    Y que un empleado inició sesión en el panel

  Escenario: Positivo – avanzar el estado del pedido
    Dado que el empleado abre el pedido "N360-0042"
    Cuando cambia el estado a "en revisión" con la observación "Coordinando por WhatsApp"
    Entonces el pedido queda "en revisión"
    Y el historial del pedido muestra el cambio con su nombre, la fecha y la observación
    Y el cliente ve el nuevo estado en "Mis pedidos"

  Escenario: Positivo – confirmar el pago verificado
    Dado que el pedido "N360-0042" está "en revisión"
    Y que el empleado verificó que recibió ₡16 000
    Cuando cambia el estado a "confirmado"
    Entonces el pedido queda "confirmado"

  Escenario: Negativo – cambio de estado no permitido
    Dado que el pedido "N360-0042" está "entregado"
    Cuando el empleado intenta pasarlo a "pendiente"
    Entonces ve "Un pedido entregado no puede cambiar de estado"
    Y el estado no cambia

  Escenario: Negativo – cancelar un pedido ya pagado
    Dado que el pedido "N360-0042" está "confirmado"
    Cuando el empleado intenta cancelarlo
    Entonces ve "Este pedido ya fue pagado: requiere revisar el reembolso"
    Y la cancelación necesita la observación del reembolso para continuar

  Escenario: Error – falla al guardar el cambio
    Dado que la API no responde
    Cuando el empleado cambia el estado de "N360-0042"
    Entonces ve "No se pudo actualizar el estado. Intentá de nuevo"
    Y el pedido sigue mostrando "pendiente"

  Esquema del escenario: Validación – transiciones de estado
    Dado que un pedido está en estado "<actual>"
    Cuando el empleado intenta pasarlo a "<nuevo>"
    Entonces el cambio <resultado>

    Ejemplos:
      | actual      | nuevo       | resultado       |
      | pendiente   | en revisión | se guarda       |
      | en revisión | confirmado  | se guarda       |
      | confirmado  | preparado   | se guarda       |
      | preparado   | entregado   | se guarda       |
      | pendiente   | entregado   | se rechaza      |
      | cancelado   | confirmado  | se rechaza      |
```
